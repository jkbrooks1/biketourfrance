# Approved copy (staging)

The staging site renders its text from a committed snapshot of the Google Sheet
`BTF_Approved_Site_Copy` (tab `Approved Site Copy`). Cloudflare never contacts Google.

## Files

- `approved-copy.snapshot.json`: the Sheet rows as fetched, with the Sheet ID, tab, fetch time, and a SHA-256 of the rows. Review changes to this file in the pull request.
- `field-map.json`: where each Sheet row sits in the Framer export (HTML and the page JavaScript modules). Generated by `scripts/copy/generate-field-map.mjs` from `site/`. Baseline text in the map describes the committed export, not the live Sheet.

## Workflow

1. Edit the Sheet.
2. Fetch a new snapshot on a Mac that holds the existing BTF service account key file. Pass the file path in the environment; the key is never read into the repo:
   `BTF_COPY_KEY_FILE=<path to key file> npm run copy:fetch`
3. Review `git diff copy/approved-copy.snapshot.json`.
4. `npm run build` renders the snapshot into `.generated/site/` (offline), then builds with Astro.
5. `npm run copy:check` checks `dist/` against the snapshot.
6. Commit and push the branch. Cloudflare Pages runs `npm run build` only.

## Rules the renderer enforces

- Every Sheet row must have a place on the site, and every mapped field must have a Sheet row. A mismatch fails the build.
- Single-line fields cannot contain line breaks.
- Two fields keep fixed text that must stay in the Sheet value, in order: the bold labels in `/footer/policies` (`Privacy Policy:`, `Terms of Service:`, `Cookie Policy:`, `Disclaimer:`) and the first words of `/ready-to-ride/cdm_heading` (`Canal des Deux Mers`). That heading also needs exactly three lines.
- The Framer page JavaScript re-renders text after load, so the renderer patches the modules as well as the HTML.

## Known limits

- The Framer search index files (`searchIndex-*.json`) still hold the original text. Nothing on the pages reads them.
- This is a staging pipeline. It is not a production deploy gate.
